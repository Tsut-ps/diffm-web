# diffm-web

動画を比べるためのツール。「2つを比較」と「複数を並べて再生」の2つのタブがあります

- **2つを比較**: 2本の動画を1フレームずつ比べて、どこがどれだけ違うかをグラフにする。エンコード設定を変えたときの画質劣化や、編集で意図せず変わった箇所を見つけるのに使えます
- **複数を並べて再生**: 複数の動画を横並び / 縦並びで、1本の共通タイムラインで同時に再生する。「2つを比較」で読み込んだ2本は、最初から入っています

- 動画を入れた側が「いまの作業」になり、もう一方のタブは初期状態に戻ります（「2つを比較」で A / B を入れると「複数を並べて再生」が空になり、開くといまの A と B だけが入ります。「複数を並べて再生」に動画を入れると、「2つを比較」の A / B と結果が空になります）
- ブラウザだけで動きます。動画はどこにも送信されません
- [Tsut-ps/diffm](https://github.com/Tsut-ps/diffm) の考え方を Web にしたものです

## 2つを比較の使い方

1. 上の A（基準）と B（比較対象）の枠に動画を入れる。枠をクリックして選ぶか、ドロップする。ウィンドウのどこにドロップしても入る（2本なら A → B、1本なら空いている枠へ）。入れ替えるときは、その枠に入れ直す。読み込むと、先頭フレームが枠に出る
2. 「開始」を押す（「停止」で途中までの結果も使えます）。枠の下の行は、左が時刻、右が動画の情報（解像度・fps・長さ・コーデック。差分の枠は、比較に使う大きさ）
3. グラフをクリックすると、そのフレームを A / B / 差分で表示（しきい値を超えた区間は、グラフ上に色付きの帯で出て、ピークに印が付きます。区間にカーソルを合わせると、範囲とピークが出ます。見出しの ⏮ ⏭ で、前後の区間のピークへ移れます）
4. グラフの見出しの「画像を ZIP で保存」（各区間のピークを PNG に。左から A | B | 差分）、「CSV で保存」（全フレームの値）

**差分の値**は、画素ごとの色の差を輝度で平均したものです。0 なら完全に同じで、最大は 255。しきい値以上が続く範囲を「区間」とします。

| キー | 動作 |
|---|---|
| ← / → | 前 / 次のフレーム（Shift で10フレーム。結果が出た後） |
| Home / End | 最初 / 最後のフレーム（結果が出た後） |
| Esc | 比較を止める（比較中） |

設定（フレームの合わせ方、比較の解像度、差分の強調、しきい値）は、次回も覚えています。

## 複数を並べて再生の使い方

1. 動画をドロップ（「動画を追加」から選んでも可。複数まとめて入れられます）。「2つを比較」で A と B を読み込んでいれば、このタブを開いたときに、最初から入っています（フレームを選んでいれば、その時刻から始まります）
2. 右上の「自動 / 横並び / 縦並び」で並べ方を切り替える。自動は、画面と動画の形から、動画が大きく映るほうを選ぶ（初期値。手動で選んだ並び方は次回も覚えています）
3. 下の再生バーで、全動画をまとめて操作する

- 再生・一時停止、シーク、速度（0.25〜2倍）、ループ、コマ送り（1/30秒）
- 動画ごとの「開始ズレ」（秒）。別々に撮った動画のタイミング合わせに使います。名前・開始ズレ・ミュート・外すボタンの帯は、縦長の枠では動画の上、横長の枠では、動画の左に、帯をそのまま -90 度回した縦タブ（下から上へ読む向き）で出ます。動画の左右にできる余白を使って、高さを動画に回すためです
- 動画ごとのミュートと、まとめてミュート（音は最初の1本だけ鳴る状態で始まります）
- 再生は `<video>` を使うため、再生できる形式はブラウザ次第です（mp4 / mov / webm など）。「2つを比較」で読めても、再生できない形式があります
- 同期は、共通の時計に各動画の再生位置を合わせて取ります。再生を始めるときは、全動画が動き出すのを待ってから時計を進めます（シーク直後は、キーフレームの間隔が長い動画ほど動き出しが遅いため）。再生中のズレは、0.03秒以下なら放置、0.2秒までは再生速度を最大±15%変えて解消（シークしないのでカクつかない）、それ以上は位置を合わせ直します。一時停止・シーク・コマ送りのときは全動画を同じ位置に揃えます。何本も同時に再生すると、端末の性能によってはずれることがあります

| キー | 動作 |
|---|---|
| Space | 再生 / 一時停止 |
| ← / → | 1コマ戻る / 進む（Shift で5秒） |
| Home / End | 先頭 / 末尾 |
| M | すべてミュート |

## 比較の設定

| 項目 | 内容 |
|---|---|
| フレームの合わせ方 | A のどのフレームと B のどのフレームを比べるか（下の表）。初期値は自動 |
| 比較の解像度 | 差分を計算するときに、縦横をこの割合に縮小する（50% なら画素数は 1/4）。小さいほど速く、細かい差は見逃しやすい。差分の枠の右に、実際に使った大きさが出る |
| 途中経過の更新 | 比較している最中に、差分の画像とグラフを、1秒に何回描き直すか。初期値は自動（描くのにかかった時間に合わせて、約8回/秒を上限に間を空ける）。選べるのは、全フレーム / 最大 30 / 10 / 5 / 1 回/秒（1秒に最大で何回。比較が追いつかないときは、届かない）。全フレームは、見逃したくないときに使う。比較が半分ほどの速さになる（1080p で 98 → 52 fps）。30 回/秒は2割ほど遅くなる。結果には影響しない |
| 差分の強調 | 差分画像の表示倍率。値には影響しない |
| しきい値 | 「違う」とみなす値。終了後に変えると区間もすぐ更新される |

## フレームの合わせ方

| 方法 | 内容 |
|---|---|
| フレーム番号 | A の n 番目と B の n 番目を比べる。どちらかが尽きたら終了 |
| 時刻 | A の各フレームの時刻に表示されている B のフレームを当てる（B は重複・欠落する） |
| 自動（初期値） | fps が違えば時刻、同じならフレーム番号 |

## 警告

比較条件が違うと画面に警告を出します（比較は続行）。

- 解像度が違う: B を A の大きさに拡縮する（縦横比が違えば引き伸ばす）
- fps が違う: 合わせ方に応じた注意
- 長さが違う: 短い方に合わせる

## 動作環境と制約

- WebCodecs が使えるモダンブラウザが必要。デコードできるコーデックはブラウザ次第（H.264 / VP9 / AV1 など）で、読めない動画は読み込み時にエラー
- 解像度は 1 辺 4096px まで（4K UHD / DCI 4K を含む）。超えると読み込み時に断る
- 外部へは通信しない（CSP で通信先を許可していない。許可しているのは、ワーカーと動画再生のためのローカルな `blob:` のみ）

## 速さの目安

1秒あたりに比べられるフレーム数（fps）の実測です。動画の絵の細かさやビットレートで変わります。

| 環境 | 動画 | 比較の解像度（縦横の縮小率） | fps |
|---|---|---|---|
| GPU なしのヘッドレス Chrome | 1080p | 100% | 約 14〜18 |
| GPU なしのヘッドレス Chrome | 4K | 100% | 約 1.5〜3 |
| Ryzen 9 9950X3D + RTX 5070 Ti、Chrome | 1080p（H.264 / VP9 / AV1 / HEVC） | 100% | 約 92〜97 |
| 同上 | 1080p（H.264、細かい絵・約 260Mbps） | 100% | 約 57 |
| 同上 | 1080p（H.264） | 50% / 25% | 約 238 / 395 |
| 同上 | 4K（H.264 / AV1） | 100% | 約 25〜27 |
| 同上 | 4K（H.264） | 50% | 約 74 |

Ryzen + RTX の行は、10 秒・30fps の合成映像を A と B の両方に入れて、1回測った値です。実写では変わります。

## 仕組み

[mediabunny](https://mediabunny.dev/) と WebCodecs で、2本を先頭から順にデコードします。シークしないので、フレームはずれません。
記録するのは数値とタイムスタンプだけで、画像は表示・保存のときに、そのフレームだけ再デコードします。

## 開発

Node.js 24（`.node-version` で固定。Workers Builds もこれを使う）。

```
npm ci --ignore-scripts
npm run dev        # 開発サーバー（http://localhost:5173/）
npm run typecheck  # 型チェック
npm run build      # 型チェックの後、dist/ に出力
npm run preview    # dist/ の確認（meta の CSP のみ。応答ヘッダーも見るなら npx wrangler dev）
```

- 開発サーバーは自分の PC からだけ使う（`--host` で公開しない）
- CSP はビルド時だけ付く（開発サーバーと両立しないため）
- mediabunny の更新: `npm install --ignore-scripts --save-exact mediabunny@<版>` の後、`vite.config.ts` と `index.html` の版とソース URL も直す

```
src/
  app.ts       エントリーポイント（イベントを各機能につなぐ）
  player.ts    並べて再生（共通タイムライン、動画の追加・削除、操作）
  player.css   並べて再生の見た目
  loader.ts    動画の読み込み
  compare.ts   比較の実行
  frames.ts    任意フレームの再表示
  exporter.ts  ZIP / CSV の書き出し
  types.ts     型と状態
  lib/         DOM に触らない処理（差分計算、フレームの合わせ方、ZIP）
  ui/          画面の要素、反映、グラフ、タブ、ドロップ、設定の保存
```

## 公開

Cloudflare Workers の静的アセットとして公開します（設定は `wrangler.jsonc`、配信は `dist/` のみ）。

- `main` にプッシュすると、Cloudflare の Git 連携が `npm run build` → `npx wrangler deploy` で公開
- 手元からは、`npm run build` の後に `npx wrangler deploy`
- ビルド時に `dist/_headers` を出力し、Workers が CSP を応答ヘッダーでも付ける（meta と同じ内容に、埋め込みを防ぐ `frame-ancestors 'none'` を追加。`_headers` 自体は配信されない）
